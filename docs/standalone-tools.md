# Инструменты отдельными репозиториями

Шесть демо-инструментов лендинга вынесены в самостоятельные приложения:
`bizdoctor`, `coldmessage`, `objectionkiller`, `followupbot`, `inboxzero`,
`trendsniper`. Каждый — маленькое приложение на Next.js: две локали
(`/` и `/en`), один роут `POST /api/<tool>`, свой деплой.

Здесь — не копии, а результат работы `scripts/extract-tool.py`. Это важно:
инструменты устроены одинаково, и шесть отдельных ручных копирований
разъехались бы уже на первой правке общего каркаса.

## Как пересобрать

```bash
python3 scripts/extract-tool.py                # все шесть
python3 scripts/extract-tool.py bizdoctor      # один
OUT_ROOT=~/work/tools python3 scripts/extract-tool.py
```

По умолчанию складывает в `/tmp/standalone-tools/<tool>`.

## Что скрипт меняет при переносе

| Что | Почему |
|---|---|
| Набор иконок урезается до используемых | в лендинге он общий на полсотни глифов; в отдельном репозитории сорок пять из них — мёртвый код, который читающий принимает за дизайн-набор и боится трогать |
| Словарь `content/tools.ts` урезается | из ~720 строк на десять инструментов остаются общие ключи и блок нужного |
| Из `globals.css` убираются `.reveal` и `.collapse` | обслуживают компоненты лендинга, которых в репозитории нет |
| Гарнитура — системная, без `next/font/google` | сборка репозитория не должна зависеть от сети |
| Из `rate-limit.ts` снимается крючок в ленту активности | лента — часть лендинга |
| Текст лимита не зовёт «оформить доступ» | в отдельном приложении нет формы, куда такой призыв ведёт |

## Что остаётся общим — и что с этим делать

`gemini.ts`, `rate-limit.ts`, `apiMessages.ts`, `i18n.ts`, `icons.tsx` и
`globals.css` копируются в каждый репозиторий. Это осознанный размен: пакет
на npm ради шести маленьких приложений — лишняя инфраструктура, а расхождение
лечится повторным прогоном скрипта.

Обратная сторона честная: правка в общем модуле лендинга **не** доезжает до
вынесенных репозиториев сама. Доедет — когда скрипт прогонят снова и
результат вольют.

## Лимиты

Три уровня, все по IP: десять запросов в минуту, тридцать в сутки, два в
сутки на сам инструмент. С настроенным Upstash счётчики переживают холодный
старт функции; без него живут в памяти инстанса — лимит мягче, но сервис не
падает из-за недоступного Redis.

## Переменные окружения

`GEMINI_API_KEY` обязателен. `UPSTASH_REDIS_REST_URL` и
`UPSTASH_REDIS_REST_TOKEN` — по желанию. `NEXT_PUBLIC_SITE_URL` — для
канонических ссылок в метаданных. См. `.env.example` в каждом репозитории.
